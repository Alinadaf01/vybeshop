## قواعد فایل HTML

- **یک فایل به‌ازای هر صفحه.** فایل تجمیعی چندویویی (مثل `VYBE Design.dc.html`) قابل مصرف نیست — Code باید بتواند هر صفحه را جدا بخواند
- **بدون استایل inline.** همه استایل با کلاس‌های Tailwind از CDN. اگر پوشه در دسترس نبود، اول مشکل دسترسی را گزارش کن — به استایل inline پناه نبر
- هر فایل مستقل و قابل باز شدن در مرورگر
- توکن‌ها به‌صورت CSS variable در `:root` تعریف و کلاس‌ها به آن‌ها اشاره کنند
- سه بریک‌پوینت درست کار کند: `375px · 768px · 1440px`

## `tokens.json` — ✅ آماده و قفل‌شده

**این فایل دیگر خروجی Design نیست.** مستقیماً از برند بوک (فصل ۰۵ و ۰۶) استخراج و در `design/tokens.json` قفل شده است.

دلیل: توکن‌ها **واقعیت برندی** هستند، نه تصمیم طراحی. برند بوک همه مقادیر را صریحاً تعیین کرده، پس جایی برای تفسیر نیست و نباید دو نسخه از آن وجود داشته باشد.

| نقش | مسئولیت |
|---|---|
| **Design** | `tokens.json` را **مصرف** می‌کند. تولید یا بازنویسی نمی‌کند |
| **Code** | `src/styles/tokens.css` و `tailwind.config.js` را از روی آن **بازتولید** می‌کند، نه ادغام دستی |

اگر Design یا Code به کلیدی نیاز داشت که در فایل نیست، **حدس نمی‌زند** — در `design/NOTES.md` درخواست ثبت می‌کند تا اضافه شود.

### دو تناقض برند بوک که در این فایل حل شده‌اند

۱. **وزن Display:** جدول مقیاس تایپوگرافی «Bold» می‌گوید، ولی جدول سیستم فونت برای «نمایش فارسی» صریحاً «پیدا اکسترابولد» را تعیین کرده. چون دومی مشخص‌تر است، `display` و `h1` روی وزن **۸۰۰** قفل شدند.

۲. **جای لوگو:** برند بوک «بالا، سمت چپ» را برای چیدمان LTR گفته. معادل RTL آن **بالا سمت راست** است و همان در فایل ثبت شده.

**جزئیات فونت‌ها:**

هر چهار وزن از TTF اصلی به woff2 تبدیل و برای فارسی زیرمجموعه‌سازی شدند:

```

Peyda-Medium.woff2      500   29.1 KB
Peyda-SemiBold.woff2    600   28.8 KB
Peyda-Bold.woff2        700   27.2 KB
Peyda-ExtraBold.woff2   800   28.6 KB
                        مجموع 120 KB

> وزن ۶۰۰ بعداً اضافه شد چون فایل‌های Design در مجموع ۷۷ بار از `font-semibold` استفاده کرده‌اند.

- بازه یونیکد: لاتین پایه + عربی/فارسی + فرم‌های نمایشی عربی + ZWNJ + نشانه‌گذاری
- پوشش تأیید شد: اعداد فارسی و لاتین، نیم‌فاصله، و همه حروف فارسی موجودند

- وزن‌های Thin/ExtraLight/Light/SemiBold/Black تبدیل نشدند چون برند بوک آن‌ها را تعریف نکرده. اگر لازم شد، فایل TTF‌شان موجود است

> ⚠️ **`src/styles/fonts.css` باید به‌روزرسانی شود:** فعلاً فقط ۴۰۰/۵۰۰/۷۰۰ را تعریف کرده و به `.woff` هم اشاره می‌کند که وجود ندارد. باید وزن **۸۰۰ (ExtraBold)** اضافه و مسیرهای `.woff` حذف شوند — فقط `.woff2` داریم.

> 🔒 **لایسنس:** فونت پیدا محصول [فونت‌ایران](https://fontiran.com) است. برای استفاده تجاری لایسنس رسمی لازم است — این را جدا از کار فنی پیگیری کن.

```
۱. Design صفحات روز را در design/ می‌نویسد

## ⚠️ تله کلاس‌های Tailwind — قبل از تبدیل هر صفحه بخوان

Design با **Tailwind از CDN** کار می‌کند، یعنی مقیاس‌های **پیش‌فرض**.
Code مقیاس‌ها را در `tailwind.config.js` **جایگزین** کرده (نه extend)، یعنی مقیاس‌های **توکنی**.

نتیجه: کلاس‌های استاندارد Tailwind در پروژه **بی‌صدا بی‌اثر** می‌شوند — نه خطا می‌دهند، نه هشدار. فقط استایل اعمال نمی‌شود.

شمارش فعلی در فایل‌های `design/`:

| کلاس Design | معادل پروژه | تعداد |
|---|---|---|
| `text-sm` | `text-small` | **۱۶۳** |
| `rounded-md` | ✅ موجود | ۸۱ |
| `rounded-lg` | ✅ موجود | ۵۴ |
| `rounded-sm` | ✅ موجود | ۵۲ |
| `rounded-xl` | ✅ موجود | ۴ |

### قاعده اجباری

**قبل از تبدیل هر فایل HTML به React، اسکریپت اعتبارسنجی کلاس را اجرا کن:**

```
npm run check:classes -- design/05-product-detail.html
```

این اسکریپت باید همه `class="..."` را استخراج کند و هر کلاسی که در پیکربندی Tailwind پروژه resolve نمی‌شود را فهرست کند.

بدون این، هر صفحه‌ای که تبدیل می‌شود چند ده باگ خاموش وارد پروژه می‌کند. یک بار پیدا کردن `text-sm` کافی نیست — ۱۶۳ مورد دیگر در راه است.
