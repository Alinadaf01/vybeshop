# راهنمای اجرا — دیپلوی بک‌اند VYBE

این سند دقیقاً می‌گوید چه کار کنی، مرحله به مرحله. برای جزئیات فنی هر مرحله، خود `deploy/setup.sh` را ببین — این سند فقط «چه کار کن، چه ببین».

**معماری:** فروشگاه روی Vercel می‌ماند. فقط `api.vybeshop.ir` (بک‌اند جنگو) و `admin.vybeshop.ir` (پنل ادمین) روی این سرور می‌آیند.

**بعد از هر مرحله:** خروجی ترمینال، مخصوصاً بخش «===== STAGE N SUMMARY =====» در انتهای هر مرحله را کپی کن و برایم بفرست.

## مرحله ۱ — سخت‌سازی سرور

با root وارد سرور شو:

```bash
ssh root@212.23.201.146
```

کد را دانلود کن (چون `deploy/setup.sh` هنوز خودش را کلون نکرده، فقط همین یک فایل را دستی می‌گیریم؛ بقیه ریپو در مرحله ۳ کلون می‌شود):

```bash
curl -fsSL https://raw.githubusercontent.com/Alinadaf01/vybeshop/main/deploy/setup.sh -o /root/setup.sh
chmod +x /root/setup.sh
```

اجرا:

```bash
/root/setup.sh 1
```

**چه می‌بینی اگر درست بود:** خلاصه پایانی کاربر `deploy` را نشان می‌دهد، `ufw` را «active» نشان می‌دهد با فقط ۲۲/۸۰/۴۴۳، `fail2ban: active`، `timezone: Asia/Tehran`، و حداقل یک دستگاه سواپ فعال.

**بعدش چیکار کن:** از سشن خارج شو (`exit`) و دوباره وارد شو، این‌بار به‌عنوان `deploy`:

```bash
ssh deploy@212.23.201.146
```

(همان کلیدی که برای root استفاده می‌کردی، خودکار برای deploy هم کپی شده.)

⚠️ اگر این ورود جدید کار نکرد، **دوباره با root وارد شو** (سشن قبلی را نبند تا این را چک نکردی) و مشکل authorized_keys کاربر deploy را بررسی کن.

## مرحله ۲ — نصب Docker

از این به بعد همه‌چیز با کاربر `deploy` است، نه root.

```bash
git clone https://github.com/Alinadaf01/vybeshop.git /tmp/vybeshop-tmp
/tmp/vybeshop-tmp/deploy/setup.sh 2
```

(دلیل کلون موقت در `/tmp`: مرحله ۳ کلون واقعی و دائمی را در `/opt/vybeshop` انجام می‌دهد — این یکی فقط برای دسترسی به خود اسکریپت است.)

**چه می‌بینی اگر درست بود:** نسخه docker و docker compose چاپ می‌شود، «hello-world test: پاس».

اگر همین الان به گروه docker اضافه شدی (پیام «از سشن خارج شو» دیدی)، دوباره خارج شو و با `ssh deploy@212.23.201.146` وارد شو، بعد مرحله ۲ را **دوباره اجرا کن** (idempotent است، مشکلی پیش نمی‌آید) تا مطمئن شوی همه‌چیز واقعاً کار می‌کند.

از این به بعد همه دستورات را از داخل `/opt/vybeshop` اجرا کن:

## مرحله ۵ — انتقال دیتابیس و media (از دستگاه خودت)

این مرحله دو تکه دارد: **کاری که روی دستگاه خودت (ویندوز) انجام می‌دهی**، و **کاری که روی سرور اجرا می‌کنی**.

### ۵.الف) روی دستگاه خودت (ویندوز، Git Bash یا PowerShell)

از داخل پوشه پروژه (`C:\Users\Ali Nadaf\Documents\VybeShop`):

```bash
# دامپ دیتابیس توسعه
docker compose -f backend/docker-compose.yml exec db pg_dump -U vybeshop -Fc vybeshop > db.dump

# آرشیو پوشه media (تصاویر آپلودشده)
tar czf media.tar.gz -C backend/media .
```

بعد این دو فایل را به سرور آپلود کن (IP و مسیر دقیق):

```bash
scp db.dump media.tar.gz deploy@212.23.201.146:/opt/vybeshop/deploy/incoming/
```

### ۵.ب) روی سرور

```bash
./deploy/setup.sh 5
```

این مرحله اول یک تأیید می‌خواهد (چون دیتابیس فعلی سرور را جایگزین می‌کند). قبل از هرکاری خودش یک بک‌آپ از وضعیت فعلی سرور می‌گیرد؛ اگر بازیابی شکست بخورد، خودکار به همان بک‌آپ برمی‌گردد.

**چه می‌بینی اگر درست بود:** «بازیابی دیتابیس موفق بود»، تعداد محصولات و مقالات بلاگ (باید با چیزی که روی توسعه داری یکی باشد — نُه محصول، دوازده مقاله)، و «تست تصویر واقعی: پاس».

اگر «رد شد» یا «⚠️» دیدی برای تست تصویر، یعنی فایل‌های media درست منتقل نشده‌اند — این را بدون رفع کردن به مرحله بعد نبر.

## مرحله ۸ — بررسی نهایی

```bash
./deploy/setup.sh 8
```

**چه می‌بینی اگر درست بود:** لیست ✅/❌ برای هر چک، و در پایان «نتیجه کلی: ۹ پاس، ۰ رد شد» یا نزدیک به آن (rate limit ممکن است در تست تعداد کمی بالاتر/پایین‌تر باشد، طبیعی است).

بعد از این مرحله، یک بار سرور را کامل ریستارت کن:

```bash

```

چند دقیقه صبر کن، دوباره وارد شو، و مرحله ۸ را **یک‌بار دیگر** اجرا کن — باید همان نتیجه را بدون هیچ کار دستی بدهد (یعنی `restart: unless-stopped` واقعاً کار می‌کند).

## بعد از تمام مراحل — کارهای خارج از این اسکریپت

این‌ها را خودت یا با کمک من انجام بده، نه با `setup.sh`:

1. **حساب ادمین اول:**
   ```bash
   cd /opt/vybeshop
   docker compose --env-file .env.production -f docker-compose.prod.yml exec web python manage.py createsuperuser
   ```
   شماره موبایل: `09127576576`. رمز را همین‌جا در ترمینال خودت وارد می‌کنی — من نمی‌بینمش.

2. **پوش کردن کامیت‌ها به گیت‌هاب** (از دستگاه خودت):
   ```bash
   git push
   ```

3. **Vercel:** در پروژه فروشگاه، `VITE_API_BASE_URL` را روی `https://api.vybeshop.ir/api` بگذار و دیپلوی مجدد بزن.

4. **تأیید اتصال واقعی فروشگاه به بک‌اند:** فروشگاه را در مرورگر باز کن، تب Network دواتولز را باز کن، و ببین درخواست‌ها واقعاً به `api.vybeshop.ir` می‌روند (نه اینکه صفحه سالم به‌نظر برسد ولی از داده fake محلی بخواند — این خیلی مهم است چون fallback فعال می‌ماند و ظاهر یکسان می‌دهد حتی اگر وصل نباشد).

5. **کلیدهای واقعی کاوه‌نگار/زرین‌پال:** از پنل `admin.vybeshop.ir` → تنظیمات → کلیدهای API، طبق `SETUP-GUIDE.md`.

6. **رابط کاربری مدیریت رمز در پنل ادمین** (بخش ۶ تسک) — کار جداگانه‌ای است، بعد از بالا آمدن سرور با من هماهنگ کن.

7. **`HANDOVER.md`** — بعد از همه موارد بالا می‌نویسمش.

## قوانین ایمنی که هرگز نباید زیر پا گذاشته شوند

- **هرگز** `docker compose down -v` را روی این سرور اجرا نکن — `-v` تمام volumeها (دیتابیس، media) را پاک می‌کند، حتی اگر نام‌دار باشند.
- اگر مرحله‌ای شکست خورد، **دوباره از همان شماره اجرا کن**، نه از اول — هر مرحله idempotent است.
- اگر مرحله ۵ (انتقال دیتابیس) را دوباره اجرا کنی *بعد از اینکه سایت واقعی زنده شده و سفارش واقعی داشته*، هر سفارشی که بعد از اولین انتقال ثبت شده پاک می‌شود (چون دوباره جایگزین می‌شود). این مرحله فقط برای انتقال اولیه است، نه یک عملیات معمولی.
